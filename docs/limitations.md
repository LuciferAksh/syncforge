# Limits and operating assumptions

- **Single local server.** Loopback binding is intentional. There is no public hosting configuration, TLS termination, email verification, account recovery, MFA, CSRF token rotation, or multi-tenant cloud operations layer. Do not expose the demo through a public tunnel.
- **Not end-to-end encrypted.** The local server can read document contents. SQLite and IndexedDB data are not encrypted by this application. A future hosted deployment needs HTTPS/WSS, Secure cookies, proper deployment controls, backups, and an authentication review.
- **Device data can disappear.** Browser quota, eviction, private browsing, cleared site data, disk failure, and profile removal can destroy a local copy. Export important work. If device persistence fails, the UI warns and does not claim a completed local save.
- **Offline scope is explicit.** A first successful online visit is required to cache the shell and each document. Sign-in, registration, document creation, titles, and sharing need the server. The cached library may require Retry after server recovery. Clearing or changing permissions does not automatically rewrite old metadata in every open tab.
- **Revocation is prospective.** Previously downloaded copies cannot be remotely erased. An open blocked document remains exportable; navigating away from a revoked document may make its old cached copy available only through browser storage tools. Sign-out deliberately preserves device copies; use a separate browser profile on shared computers. Tabs in one profile share cookies, so use separate profiles for different accounts.
- **Bounded payloads.** Text is limited to 200,000 UTF-16 code units, individual binary updates to 512 KiB, total encoded document state to 2 MiB, WebSocket frames to 750 KiB, and HTTP JSON bodies to 512 KiB. Protocol limits can reject a large reconnect batch even if the text alone fits. Export the local draft rather than closing it after a rejection.
- **Bounded active state.** Up to 100 active document rooms and 50 connections per room, 100 document frames per connection per second, 100 documents per owner, and 200 registered accounts. The local sign-in/registration rate limit is shared by source IP. SQLite operations and candidate-state validation run on the server thread.
- **Compaction is not unlimited storage.** Yjs retains CRDT history/tombstones as required by its model. Snapshot compaction reduces the update log, while delivery receipts and activity rows continue growing. There is no storage retention policy or automated database backup.
- **Durability has a boundary.** WAL and synchronous FULL protect acknowledged transactions within SQLite's guarantees and the underlying OS/storage behavior. No claim covers disk corruption, hardware loss, multi-region failure, or every possible abrupt shutdown. Automated restart tests use orderly server restarts; they are not exhaustive power-loss tests.
- **Convergence is not semantic correctness.** Concurrent valid edits converge when delivered, but the resulting prose may still need human editing. Authorization changes intentionally prevent unauthorized updates from reaching the shared document. Yjs is the CRDT engine, not a newly invented SyncForge algorithm.
- **Activity is not version history.** Events show accepted updates, compaction, creation, renaming, and sharing actions. There is no document deletion, snapshot browser, or restore-to-revision UI in this release.
- **No production benchmark.** The automated suite and browser demonstrations verify controlled correctness cases, not a published throughput, latency, security, or large-team scale guarantee.
